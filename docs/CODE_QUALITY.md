# 代码与注释规范

本框架采用逐声明严格审查：每一个模块、变量、参数、方法、函数、类、组件均需紧邻且具体的中文说明。内容解释契约、状态和生命周期，范围包括全部局部量、解构绑定、闭包参数、异常绑定和测试夹具；不能以“变量自解释”为由跳过。

本仓库按逐文件阅读、声明与回调清单、语义比对、静态规则和运行态检查共同复核。扫描匹配到注释不等于说明正确；修改后仍需核对注释指向的作用域、参数来源和真实行为。

## 文件与依赖

每个手写源码文件开头说明模块职责、输入来源、状态归属和关键限制；末尾保留模块结束标记。配置、样式也说明影响范围：环境值是构建时还是运行时，哪个容器分配高度，哪个节点允许滚动。

导入说明对应真实依赖用途。例如 `useAntdTable` 持有查询和分页最新结果，忽略旧结果并不代表底层网络已取消；上传类型预设只做客户端提示，不能代替服务端内容检查。避免只写“引入依赖”“工具方法”或把目录名翻译一遍。

## 组件、函数与状态

- 组件公开参数写清类型、默认值、单位、受控/非受控模式、回调入参与返回值。ref 仅列出实际实现的方法。
- 全部函数、方法与回调说明参数来源、返回结果、失败/抛错语义和边界值。回调的 Promise、同步校验要求和取消责任不能省略。
- 类、构造函数、字段、全部局部变量说明真实含义、来源、约束、状态变化与 owner。锁、代次、uid、临时 URL 分别解释所防止的问题和清理时机。
- 循环变量、函数与方法参数、闭包参数、catch 绑定、解构别名、状态值与更新函数均逐项检查。分组注释必须逐个点名解释，不用一条泛化说明代替所有绑定。
- 异步分支解释关闭、重开、切换会话、缓存页面和卸载后的结果如何处理。既不把取消信号描述成服务端回滚，也不把 loading 描述成后端幂等。
- 单位写在声明或 API 契约附近：毫秒、CSS 像素、百分比、MiB。默认值必须与实现一致。

注释解释含义、契约、原因和影响，不机械复述赋值或 JSX 标签。简短回调可以就近说明，但参数含义、数据来源和动作边界不能遗漏；有名称的绑定在说明文字中用反引号标识。测试夹具说明具体故障输入和预期边界，不用模板说明充数。

## 错误、权限与资源

传输层只返回原始响应，服务适配器根据真实契约判断业务成功。缺少接口契约时不猜成功码。失败不得伪装成空列表或成功结果；可恢复错误提供明确反馈并释放动作锁。

认证来源固定，会话变化后旧结果不得覆盖新用户状态。日志不直接输出请求配置、凭证或原始敏感响应。上传目标授权、资源协议、浏览器编码回退的 MIME 与扩展名分别检查，不把文件名/扩展名当作内容验证。

后台外壳不滚动，搜索、表格、长表单和弹层正文分别在组件内滚动。CSS 的 `overflow:hidden` 必须有相邻的有界滚动容器与实际可达性证据；不能靠隐藏溢出掩盖操作入口。

## 格式限制与例外

| 文件类型 | 维护方式 |
| --- | --- |
| 手写 JS / JSX / LESS 与注释支持的配置 | 使用上述文件、依赖、方法、状态和边界说明 |
| Jest 测试 | 测试名称说明输入与期望，全部夹具变量和回调参数同样逐项审查，明确替身与真实环境的区别 |
| `package.json`、锁文件等严格 JSON | 保持标准格式，命令和约束写在 README 与文档中 |
| Umi 生成目录、构建产物、第三方依赖 | 不手工添加注释，不纳入手写源码覆盖结论 |
| 图片、字体和其它二进制资源 | 不写伪注释，以文件用途和来源说明维护 |
| YAML 等其它配置 | 按格式支持补充触发条件和步骤职责；本框架当前未内置 CI workflow |

## 修改后的检查

先运行最近的组件/工具回归，再执行 `npm run verify`（Lint → 格式 → 测试 → 生产构建）。布局改动还需在实际浏览器检查桌面、窄屏、短窗口、长内容及失败恢复。

注释修改单独核对非注释语法与编译后 CSS，功能修改明确列出行为差异并补回归用例。自动检查用于发现遗漏和可疑模板，最终仍需按实际实现人工检查说明是否准确。检查脚本不能证明任意后端、浏览器和新增业务页面永远无问题。
